## 🚀 Featured Projects

<details>
<summary><b>🏠 Smart Home NIDS — ML-Based Network Intrusion Detection</b></summary>
<br/>

A machine learning intrusion detection pipeline for smart-home traffic, built
around a Random Forest classifier with a SQLite persistence layer and a
Streamlit front end, and validated with a thorough automated test suite.

| Attribute | Detail |
|---|---|
| **Stack** | Python, scikit-learn, PyTest, Scapy, SHAP, Streamlit, Docker |
| **Scale** | 7.8M-record intrusion detection pipeline |
| **Testing** | 27-test PyTest suite (100% pass) covering schema validation, database persistence and data-generation edge cases, using isolated fixtures |
| **Bug Caught** | ICMP was never mapped in the encoder and would have thrown an uncaught error at inference. Found by testing the classifier against every declared traffic type |
| **Fix** | Pipeline ran on 8 features vs. 18 documented. Traced through the SMOTEENN-balanced preprocessing, fixed it, and added regression tests pinning the feature contract |
| **Repository** | [github.com/Hrsh69/smart-home-nids](https://github.com/Hrsh69) |

</details>

<details>
<summary><b>🔬 Home IoT Security Lab — MITRE ATT&CK-Validated Detection Lab</b></summary>
<br/>

A home lab for measuring how well layered detection actually performs.
Controlled attacks are run against IoT targets and every alert is checked
against a MITRE ATT&CK-mapped ground-truth timeline.

| Attribute | Detail |
|---|---|
| **Stack** | Kali Linux, Suricata, Wazuh, Metasploit, MITRE ATT&CK, Ansible |
| **Scope** | Detection performance tracked across three independent layers |
| **Method** | Controlled Nmap and Metasploit scenarios run with minimal supervision |
| **Output** | Documented coverage-gap report on false-negative and false-positive patterns across Suricata and Wazuh, cross-referencing alert logs with the attack timeline |
| **Repository** | [github.com/Hrsh69/iot-security-lab](https://github.com/Hrsh69) |

</details>

<details>
<summary><b>⚡ API Rate Limiter — FastAPI Rate-Limiting Library</b></summary>
<br/>

A rate-limiting library for FastAPI with three ways to plug in and three
algorithms behind one unified interface, designed to keep protecting an API
even when its backing store goes down.

| Attribute | Detail |
|---|---|
| **Stack** | Python, FastAPI, Redis, uv, AsyncIO |
| **Entry Points** | Middleware, decorator and dependency injection |
| **Algorithms** | Sliding Window, Token Bucket and Fixed Window behind a single interface |
| **Resilience** | Throttling keeps running through Redis outages via automatic in-memory fallback |
| **Control** | Scoped per-endpoint limiters and multi-tier client fingerprinting (RELAXED / NORMAL / STRICT) with most-restrictive-limit stacking |
| **Repository** | [github.com/Hrsh69/api-rate-limiter](https://github.com/Hrsh69) |

</details>
